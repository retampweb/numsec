# Numsec Chat Commands Protocol

This file is the entry point for assistants (Cursor, Windsurf, Trae, ...). It defines
what `/numsec "..."` means inside this project.

## Where the truth lives

| Path | What it holds |
| --- | --- |
| `numsec/project.md` | what the project does, what data it handles, trust boundaries |
| `numsec/architecture.md` | components, data flows, external integrations |
| `numsec/security-requirements.md` | requirements, assumptions, out-of-scope items |
| `numsec/threats/THREAT-*/threat.md` | findings produced by `numsec analyze` |
| `numsec/changes/<change-id>/` | proposed changes: proposal, tasks, spec deltas |

Generated threats are marked `<!-- generated by numsec -->` and are refreshed on
every `numsec analyze`. Do not edit them by hand; keep your own notes in a separate
file next to them.

## Chat commands

These are handled by *you*, the assistant, on top of the CLI.

- `/numsec "analyze"` — run `numsec analyze --ai-format`, then read every generated
  `threat.md`. Summarise findings by severity instead of dumping files.
- `/numsec "fix THREAT-001"` — write a change proposal to
  `numsec/changes/FIX-THREAT-001/` (`proposal.md`, `tasks.md`) and stop there:
  the patch itself needs review.
- `/numsec "apply FIX-THREAT-001"` — apply the reviewed change and report the diff.

## Change policy

Anything that touches authentication, authorisation, secret handling, external
input or deployment gets a change proposal under `numsec/changes/` before code.

## Output expectations

Every response states: what you read, what you plan to do, what you changed.
